# Домашнє завдання: усунення брязкоту контактів кнопки

## Мета

Дослідити брязкіт контактів механічної кнопки, реалізувати програмні способи його усунення (debounce) та порівняти їхню роботу з апаратним RC-фільтром і без нього.

## Загальні вимоги

- Використовувати Arduino Framework або ESP-IDF. Поточний проєкт налаштований на Arduino у PlatformIO для Adafruit Feather ESP32-S3.
- Опублікувати код і результати виконання на GitHub.
- Додати посилання на репозиторій у LMS.
- Для кожного методу зберегти результати вимірювань і короткий висновок.

Реалізації дослідів збережено в `examples/`; поточний `src/main.cpp` містить Polling із RC. Фактичні результати та висновки наведено у [REPORT.md](REPORT.md).

## 1. Базова реалізація без debounce

1. Налаштувати GPIO-переривання за спадним фронтом (`FALLING`).
2. Для кожного переривання інкрементувати лічильник.
3. Виводити значення лічильника в лог з основного циклу або задачі, поза обробником переривання (ISR).
4. Перевірити поведінку під час натискання та відпускання кнопки.

**Очікувані спостереження:** одне фізичне натискання може спричинити кілька переривань. Через брязкіт спадні фронти можливі також під час відпускання кнопки.

## 2. Програмний debounce за часом (time-based)

1. Додати перевірку часу між подіями: ігнорувати подію, якщо від попереднього переривання минуло менше ніж **50 мс**.
2. Виконувати перевірку й обробку подій поза ISR, у `loop()` або задачі.
3. Зафіксувати в описі реалізації, коли оновлюється час попередньої події, щоб можна було відтворити експеримент.
4. Повторити перевірку натискання та відпускання.

**Очікувані спостереження:** кількість хибних спрацювань зменшується, але спрацювання під час відпускання все ще можливі.

## 3. Програмний debounce за станом (state-based)

1. В ISR лише сигналізувати про подію.
2. У `loop()` або задачі перевіряти, чи кнопка досі натиснута.
3. Приймати підтверджене натискання лише один раз; ігнорувати повторні події до підтвердженого стабільного відпускання.
4. Події під час відпускання не повинні виконувати дію натискання.

**Цільовий результат:** рівно одна реакція на одне фізичне натискання; відпускання не викликає дії.

> Однієї миттєвої перевірки рівня недостатньо для гарантованого усунення брязкоту. Потрібні підтвердження стабільного стану та повторний дозвіл обробки лише після стабільного відпускання. Спосіб підтвердження і його часові параметри зазначити у звіті.

## 4. Опитування кнопки з debounce (polling)

1. Повністю вимкнути GPIO-переривання для кнопки.
2. Опитувати кнопку кожні **5–10 мс**.
3. Реалізувати debounce як машину станів: відпущена → підтвердження натискання → натиснута → підтвердження відпускання.
4. Виконувати дію лише під час переходу до підтвердженого стану «натиснута».
5. Зафіксувати інтервал опитування та час підтвердження стану.

**Очікувані спостереження:** стабільна реакція без повторів; затримка залежить від інтервалу опитування й часу підтвердження стану. Порівняти її з попередніми методами за вимірюваннями.

## 5. Апаратний debounce: RC-фільтр

1. Додати RC-фільтр із такими компонентами:
   - конденсатор — **100 нФ** (`100n`);
   - резистор — **100 Ом** (`100R`);
   - підтягувальний резистор залишити незмінним — **10 кОм** (`10k`).
2. Зберегти схему або фото підключення.
3. Повторити завдання **1–4** із RC-фільтром.
4. Для кожного методу порівняти кількість хибних спрацювань і затримку з RC-фільтром та без нього.

**Очікувані спостереження:** RC-фільтр може зменшити вплив брязкоту. Фактичну ефективність визначити експериментально.

**Позначення:**

- **Фізичні натискання** — кількість навмисних натискань кнопки.
- **Зараховані дії** — усі реакції програми, що збільшили лічильник дій після застосування відповідного методу.
- **Хибні дії** — зайві реакції: повтори одного натискання, дії при відпусканні та дії без натискання.
- **Пропущені натискання** — фізичні натискання, які не спричинили жодної коректної реакції.
- **Дії при відпусканні** — частина хибних дій; не додавати їх до кількості хибних дій повторно.
- **Затримка** — час від фізичного натискання до зарахованої коректної дії. Для всіх методів використовувати однаковий спосіб визначення моменту натискання; якщо виміряти неможливо, зазначити «не виміряно».

Хибні дії та пропуски рахувати окремо: різниця між загальною кількістю дій і N сама по собі не показує кількість хибних спрацювань. Кількість сирих переривань за потреби записувати в коментарі окремо від зарахованих дій.
